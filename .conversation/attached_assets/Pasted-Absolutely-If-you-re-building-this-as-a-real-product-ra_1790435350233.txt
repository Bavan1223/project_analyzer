# 🌐 12. Offline Support

This is a **very good feature**, but important distinction:

### What should work offline?

The **frontend** can continue working when internet disappears.

For example:

```text
Internet ❌

User opens Compose
↓
Writes email
↓
Uploads CSV
↓
Creates campaign
↓
Everything saved locally
```

Then:

```text
Internet returns ✅

↓
Application detects connection
↓
Synchronizes with backend
↓
Campaign gets created
↓
Server starts scheduling
```

### Important limitation

The browser **cannot actually send the emails while completely offline**, because the backend/SMTP/Redis are unavailable.

Instead:

> **Offline = user can continue preparing work.**

> **Online = system synchronizes and actual email processing happens.**
